# Google Colab Setup & Authentication Guide

This guide provides complete instructions for authenticating `colab-agent-bridge` with Google Cloud, managing OAuth2 and Application Default Credentials (ADC), and monitoring Colab Pro/Pro+ compute unit consumption.

---

## 1. Authentication Overview

`colab-agent-bridge` relies on the underlying `google-colab-cli` to interact with Colab's VM assignment service. Google Colab supports two distinct authentication strategies:

1. **Application Default Credentials (ADC) — Recommended:** Seamless, persistent credential tokens generated by the Google Cloud SDK (`gcloud`). Best suited for developer workstations, continuous integration, and autonomous agents.
2. **Interactive OAuth2 (InstalledAppFlow):** Uses a local browser OAuth callback flow with a client ID and secret (`~/.colab-cli-oauth-config.json`).

---

## 2. Setting Up Application Default Credentials (ADC)

ADC is the default and recommended authentication strategy for `colab-agent-bridge`.

### The 4-Scope Requirement

Standard `gcloud auth login` or default ADC commands only request cloud platform scopes, which causes Colab session creation to fail with `403 Forbidden` or `DefaultCredentialsError`.

You **must** supply all four specific OAuth scopes when minting credentials:

```bash
gcloud auth application-default login \
  --scopes=openid,https://www.googleapis.com/auth/cloud-platform,https://www.googleapis.com/auth/userinfo.email,https://www.googleapis.com/auth/colaboratory
```

### Scope Breakdown

| Scope URI | Purpose |
|---|---|
| `openid` | Verifies user identity and mints standard JWT identity tokens. |
| `https://www.googleapis.com/auth/cloud-platform` | Grants authorization to query Google Cloud Platform APIs and endpoints. |
| `https://www.googleapis.com/auth/userinfo.email` | Retrieves account email to correlate subscription and quota tiers. |
| `https://www.googleapis.com/auth/colaboratory` | Grants full management of Colab runtimes, kernel assignment, and session execution. |

### Verifying ADC Authentication

Run:
```bash
colab-bridge status
```
Or directly:
```bash
/run/media/parasaran/Dev/SDK/python/install/bin/colab --auth=adc sessions
```

When properly authenticated, you will see a list of active sessions (or an empty assignment confirmation).

## 3. Interactive OAuth2 Authentication (Fallback)

If you cannot use `gcloud` ADC (e.g. within restricted corporate environments), you can configure OAuth2:

1. Visit [Google Cloud Console Credentials](https://console.cloud.google.com/apis/credentials).
2. Create an OAuth 2.0 Client ID with application type **Desktop app**.
3. Download the client secret JSON file and place it at:
   ```
   ~/.colab-cli-oauth-config.json
   ```
4. Set the authentication strategy in `.env`:
   ```bash
   COLAB_AUTH_STRATEGY=oauth2
   ```
5. Run the initial login flow:
   ```bash
   colab status
   ```
   Follow the interactive browser login prompt to authorize the application.

## 4. Colab Pro & Pro+ Compute Unit (CU) Management

Google Colab allocates GPUs and TPUs based on available Compute Units (CUs). Managing these resources prevents unexpected session termination and quota depletion.

### Checking Usage and Balances

To check your current compute unit balance and burn rate:

```bash
colab usage
```

Example output:
```text
Compute Unit Balance: 48.5 CUs
Current Usage Rate: ~1.8 CUs / hour (NVIDIA L4)
Available Runtime Tiers: Standard, Pro, Pro+
```

### Purchasing or Refilling Compute Units

If your balance is depleted, you can launch the checkout portal:

```bash
colab pay
```
This opens the Colab subscription management page where you can purchase additional pay-as-you-go compute units or upgrade tiers.

### Resource Preservation Best Practices

1. **Always Tear Down Idle Sessions:**
   Unlike standard servers, Colab continues billing for allocated VMs even if no inference requests are actively processing.
   ```bash
   colab-bridge down -s <session_name>
   ```
2. **Check for Orphaned Sessions:**
   Before starting a new job, check if any old sessions are still running:
   ```bash
   colab-bridge status
   ```
   If orphaned sessions exist:
   ```bash
   colab stop -s <orphaned_session_name>
   ```
3. **Set Realistic Model Timeouts:**
   When running `colab-bridge up`, pass `--timeout 600` (10 minutes) to prevent indefinitely waiting if a model download stalls.

## 5. Configuration Reference

`colab-agent-bridge` loads settings from environment variables or a `.env` file located in the project root:

| Variable | Default Value | Description |
|---|---|---|
| `COLAB_CLI_PATH` | `/run/media/parasaran/Dev/SDK/python/install/bin/colab` | Path to the executable `colab` CLI binary |
| `COLAB_BRIDGE_PORT` | `8000` | Local port for the forwarder tunnel and `/v1` endpoint |
| `COLAB_DEFAULT_BACKEND` | `vllm` | Default inference server (`vllm`, `ollama`, `llama_cpp`) |
| `COLAB_DEFAULT_GPU` | `T4` | Default accelerator tier (`T4`, `L4`, `A100`, `H100`, `CPU`) |
| `COLAB_AUTH_STRATEGY` | `adc` | Authentication strategy (`adc` or `oauth2`) |

## 6. Security & Credential Hygiene

- **Session State Files:** Stored under `~/.config/colab-cli/`. These files contain active VM session tokens and are ignored by git.
- **OAuth Secrets:** `~/.colab-cli-oauth-config.json` should have restricted permissions:
  ```bash
  chmod 600 ~/.colab-cli-oauth-config.json
  ```
- **Local Logs:** Temporary logs (`/content/vllm_server.log`, `/content/cloudflared.log`) remain isolated on the ephemeral Colab VM.
